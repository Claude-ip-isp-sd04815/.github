<p>演示那天出岔子，损失很难写进报表，但它真实存在：客户在那十分钟里看到的不是你的方案，是你的环境。这篇把这类支出摊开算，一共五笔——地址月费、双 ISP 溢价、备线闲置成本、演示失败的机会成本、以及你自己排查故障的时间。多数人只算了第一笔，所以才会觉得「贵的那家没必要」，算完五笔结论往往反过来。</p>

<h2>一、五笔成本，月费只占三成左右</h2>
<p>先给一个大致结构：地址月费通常占总成本的 30% 到 40%，备线闲置占 10% 上下，故障排查的人力占 20% 左右，演示失误带来的机会成本可以很高但难量化，剩下是迁移与重新适配的隐性支出。这个比例不精确，但足够说明为什么不能只看报价。</p>
<h3>可量化的四笔</h3>
<p>月费、备线费、排查工时、迁移工时，这四笔都能用数字写下来。写下来之后加总，才是可比的总成本。只看单条价格，等于只看了三分之一。</p>
<h3>难量化但必须留位置的一笔</h3>
<p>演示失败的机会成本没有准确数字，但可以设一个心理上限，比如单次演示失败折算多少工时。设了这个数，你在选方案时就有了一把尺子，而不是凭感觉。</p>

<h2>二、双 ISP 的溢价到底买到了什么</h2>
<p>双 ISP 方案通常比单线贵两成到四成。这笔溢价买的不是带宽，是两样东西：地址多样性，以及一条线出问题时还有另一条能顶。</p>
<h3>地址多样性：两个 ASN 的账</h3>
<p>两个不同运营商的 ASN，意味着你的账号可以分布在两套互相独立的地址空间里，同段密度天然减半。对于十几个账号的规模，这一条就能把关联风险压下来一截，价值是实打实的。</p>
<h3>故障冗余：一条线的保险</h3>
<p>单线方案出故障，所有账号一起停；双线方案至少有一半能继续跑。这笔保险的成本就是溢价那部分，按年算通常也就几百元，比起一次全线停摆的损失，不算贵。</p>
<p>不是所有账号都值得配双 ISP。临时号、验证号配单线甚至按量就够。把双 ISP 留给主要账号和必须稳定的演示环境，混合配置比全部上高配更省，也更合理。</p>

<h2>三、备线的钱该不该花</h2>
<p>备线是纯支出，平时不产生收益，所以最容易被砍掉。砍掉之后省下的钱是确定的，损失是不确定的，这正是它被砍的原因——人对不确定的损失天生不敏感。</p>

<h3>按停摆损失倒推备线预算</h3>
<p>算一次全线停摆的损失：停几小时、影响几个账号、折算多少工时。这个数字的十分之一，大致就是合理的年备线预算。按这个方法算，多数小团队会发现备线其实很便宜。</p>
<h3>热备不要空转</h3>
<p>空转的备线容易被当成浪费，进而被砍。让它承担低优先级任务，比如日志上传、连通性探测，既保持线路活跃，又不占用关键资源，账面也好看。</p>

<h2>四、演示环境的成本要单独算</h2>
<p>给客户演示的场景对稳定性的要求高于日常使用，因为它有时间窗口，且不能重来。这部分成本要单独列一行，别混在日常用量里，否则永远算不清。</p>
<h3>演示前一天的准备工时</h3>
<p>提前一天跑一遍完整链路、确认出口地址没变、把演示用的账号和环境单独隔离出来。这套准备通常要一到两小时，是刚性成本，省不掉。</p>
<h3>演示当天的双保险</h3>
<p>主用一条固定地址，备用一条不同 ISP 的地址，两条都提前验证过。切换动作要提前演练，别在客户面前第一次点。这一套下来，当天出岔子的概率能降到很低。</p>
<h3>归属信息的一致性检查</h3>
<p>演示时客户有时会问「你们在哪运行」，出口地址的归属地区和你的说法要对得上。演出前用 whois 看一眼机构名和地区，这是个十秒钟的动作，但能避免尴尬。</p>

<h2>五、一年账本长什么样</h2>
<p>把五笔成本按年汇总，三个方案摆在一起比较。数字是示例，比例和方法可以照搬，具体金额按自己的报价替换。</p>
<h3>低价单线方案</h3>
<p>月费低，但没有冗余，排查工时长，演示风险高。账面最漂亮，实际总成本往往不是最低，因为排查工时和机会成本都记在别的科目里。</p>
<h3>中价双 ISP 方案</h3>
<p>月费中等，有两条线可切，排查工时明显下降。对十几个账号、每月有几次演示的团队，这一档通常是总成本最低的。</p>
<h3>高配整段方案</h3>
<p>月费最高，冗余最好，但对小规模团队来说大部分容量是浪费的。等账号规模上到三十个以上，这一档的单号成本才开始有优势。</p>

<h2>常见问答</h2>
<h3>为什么便宜的方案总成本反而高？</h3>
<p>答：因为它把成本转移到了别的科目：排查时间、重配环境的工时、演示失败的损失。这些不体现在账单上，但确实发生。把它们折成钱加进去，低价方案的优势通常就消失了。</p>
<h3>演示环境能不能和日常环境共用？</h3>
<p>答：可以共用出口，但要隔离账号和配置文件。共用同一套配置文件的风险是演示前的临时操作会改动日常环境，两个场景互相干扰。</p>
<h3>备线一定要不同 ISP 吗？</h3>
<p>答：最好是。同一家运营商的两条线，在运营商侧故障时可能一起断，冗余价值大打折扣。双 ISP 的意义就在这里，买的不是带宽，是故障不相关性。</p>
<h3>排查工时怎么估才合理？</h3>
<p>答：按过去三个月的实际记录平均。没有记录就先估每月两小时，跑一个月后再修正。多数团队低估这一项，因为它分散在每天零碎的十几分钟里。</p>
